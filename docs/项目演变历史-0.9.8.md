## 0.9.8 — 补充修复：前端构建体积优化与脚本路径 bug（2026-08-07）

> 来源：构建产物 `.build` 膨胀至 4.4G 排查过程中发现的缺陷修复与优化。属于工程质量（Defect / Quality）。

### 缺陷修复（Fixed - 工程质量）

| 编号 | 变更内容 |
|---|---|
| 前端脚本 projectRoot 路径 bug | `tools/scripts/{build-app,start-server,dev-server}.mjs` 中 `projectRoot = resolve(__dirname, '..')` 指向 `tools/` 而非仓库根（脚本位于 `tools/scripts/`，向上两级才是根）。后果：`rm -rf .build/cache` 一直在删不存在的 `tools/.build/cache`，真实缓存从未被清理；dev-server 把 `data/` 误建到 `tools/data`（该目录有 `.gitkeep` 占位保留）。已统一改为 `resolve(__dirname, '../..')` |
| tsup 输出目录不一致 | `build-app.mjs` 本地构建把 `server.js` 输出到 `.build/`（与 Next `distDir` 混用），而 `tools/deploy/Dockerfile` 输出到 `dist/`，两处不一致。已统一为 `dist/server.js`（`start-server.mjs` 同步改为检查 `dist/server.js`） |

### 优化（Optimization - 构建体积）

| 编号 | 变更内容 |
|---|---|
| 构建缓存清理 | `.build` 是 Next 16 的 `distDir`，Turbopack 增量编译缓存写在 `.build/cache/` 且随构建次数无限累积（实测单次构建 118M）。已在 `build-app.mjs` 构建完成后与 `tools/deploy/Dockerfile` builder 阶段 `rm -rf .build/cache`（缓存可再生，删除仅影响下次构建速度），避免本地膨胀与镜像层膨胀 |
| 效果 | `.build` 从 4.4G（含重复依赖）降至 **44M**；`dist/server.js` 4.5KB |
| 附属 | `package.json` 新增 `clean` 脚本（`rm -rf .build dist node_modules && pnpm install`）；前端 `.gitignore` 补充 `dist/`；清理了多批残留的孤儿 dev-server 进程（tmux 会话已消失但 `pnpm dev`/`tsx watch` 仍在后台跑、持续写缓存） |

> 备注：`.build/node_modules/pino-*` 为 Turbopack 生成的 0B 符号链接占位，无害，勿删。
