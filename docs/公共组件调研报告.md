# 前后端公共组件调研报告

> 调研时间：2026-08-12
> 调研范围：CS-Web-Frontend（src/components、src/shared）、CS-Web-Backend（app/core、app/utils、app/middleware 及基类型/基仓储/基 Schema）
> 约定依据：前端 `src/components/README.md`（Atomic Design 分层）、后端 `AGENTS.md` / `CLAUDE.md`（分层与中心注册点）

---

## 一、总体结论

| 端 | 公共层位置 | 性质 |
|----|-----------|------|
| 前端 | `src/components/` | 通用 UI 组件库（Atomic Design 分层，统一从 `index.ts` 桶导出） |
| 前端 | `src/shared/` | 跨域基础设施：api 客户端、config、constants、events、feature-visibility、hooks、security、types、utils、logger |
| 后端 | `app/core/` | 与框架/基础设施强相关：配置、安全、异常、缓存、限流、队列、生命周期、日志、校验、事件、常量 |
| 后端 | `app/utils/` | 多个 service/repo 共用的纯函数 |
| 后端 | `app/middleware/` | 横切中间件（main.py 按序注册） |
| 后端 | 基类/基类型 | `models/types.py`、`repositories/base.py`、`schemas/base.py`、`models/__init__.py` |

## 二、前端公共组件

### 2.1 `src/components/` —— 通用 UI 组件库
遵循 `docs/RootDoc-FEArch.md`（Atomic Design + 目录即模块），复用阈值见 `components/README.md`（重复 ≥2 次 / 职责单一 / 可独立存在 / 可配置化）。

**primitives（atoms，无业务语义）**
- `Button` `Input`
- `Loading` / `LoadingOverlay` / `SectionLoading` / `SkeletonLine` / `SkeletonCard` / `SkeletonBlock`
- `Spinner`
- `ConfirmDialog` + `ConfirmProvider` / `useConfirm`
- `FilterBar` `InlineTabs` `SectionNav`

**layout（organisms，页面级骨架）**
- `Navbar` `Footer` `FloatingCapsuleSidebar` `CollapsingHero` `PageHeaderBackground`

**effects（视觉/动画）**
- `MobiusRing` `PageTransition` `ScrollIndicator`
- `motion-primitives`：`HERO_TIMING` / `StaggerContainer` / `RevealItem` / `RevealTitle`

**feedback（用户反馈）**
- `Toast` + `ToastProvider` / `useToast`
- `Fallback`：`LoadingFallback` / `ErrorFallback` / `GlobalErrorFallback`
- `EmptyState` `AnnouncementBanner`

**根级混合（跨域通用件）**
- `Avatar` `UserMenu` `NotificationBell` `TechTagSelector`
- `ThemeProvider` `ThemeToggle` `SWRProvider`
- `useNotificationsPreview`（hook）

> 统一出口：`src/components/index.ts`，业务侧一律 `import { Button } from '@/components'`。

### 2.2 `src/shared/` —— 跨域基础设施

| 子目录 | 关键内容 | 说明 |
|--------|---------|------|
| `api/` | `backend-api.d.ts`、`backend-client.ts` | 全局 HTTP 客户端与后端类型声明 |
| `config/` | `auth-constants`、`avatar-presets`、`admin-avatars`、`header-images` | 认证常量、头像预设、页首图等全局配置 |
| `constants/` | `breakpoints`、`logo-colors` | 断点、品牌色 |
| `events/` | `event-bus.ts`（`appBus` 单例）、`event-types.ts` | 全局事件总线 |
| `feature-visibility/` | `registry.ts`、`visibility-gate.tsx` | 功能开关门控 |
| `hooks/` | `useAuth`、`useDebounce`、`useFocusTrap`、`useCollapsingHero`、`useTopicDetail`/`useTopicActions`、`useReplyActions`、`useBreakpoint` | 全局可复用客户端 hooks |
| `security/` | `http-helpers`、`origin-guard`、`rate-limiter`（大量场景 limiter 单例）、`request-utils`、`permission-points`、`builtin-roles`、`proxy-headers`、`password`（scrypt）、`tenant-context`、`security`、`guards`、`allowed-origins`、`permissions` | HTTP 安全、校验、权限点、限流 |
| `types/` | `audit-types`、`role-types`、`user-types` | 全局 TS 类型 |
| `utils/` | `utils`（日期格式化）、`pagination`、`tech-tags`、`ui-constants`、`monitoring`、`mask`、`event-date`、`locale`、`image-utils`(server-only)、`mail`(server-only) | 纯函数工具；server-only 模块禁止从 barrel 引入 |
| 根级 | `app-error.ts`、`logger.ts`、`server-only.ts` | 应用错误封装、日志、服务端标记 |

## 三、后端公共组件

### 3.1 `app/core/` —— 基础设施（框架强相关）

**配置**
- `config.py`（`Settings` 单一配置源）
- `config_parts/`：`database`、`security`、`rate_limit`、`web`、`business`、`ops`

**安全 / 认证**
- `security.py`（密码哈希 / 令牌等认证原语）
- `security_blacklist.py`、`password_compat.py`（兼容旧哈希）、`totp.py`、`totp_encryption.py`

**异常体系（单一事实源）**
- `exceptions/`：`BaseAppException` 体系（Auth/Authorization/Validation/NotFound/Conflict/Database/ExternalService/RateLimit/Business/System 命名空间）、`ErrorCode` 注册表（禁止裸字符串）、`exception_handlers` + `ExceptionHandlerMiddleware`、`response_models`（`ErrorResponse`/`ErrorDetail`/`ErrorContext`）

**缓存 / 限流 / 队列**
- `cache/`（`cache.py`、`backends.py`）—— Redis 可降级（未配置走内存）
- `rate_limit/`（`limiter.py`、`backends.py`）
- `queue/`（`client.py`、`tasks.py`、`worker.py`）—— 异步任务队列

**生命周期 / 日志 / 可观测**
- `lifecycle/`（`registry.py` + `@register_startup` / `@register_shutdown` 自注册）
- `loguru_logger/`（`adapter`/`context`/`config`/`init`/`intercept`，统一 `get_logger`）
- `metrics.py`、`observability.py`

**其它**
- `events.py`（应用内事件机制）、`request_context.py`、`validators.py`、`constants.py`、`app_runtime.py`、`redis_client.py`、`timezone.py`（`utc_to_local`）

### 3.2 `app/utils/` —— 多 service/repo 共用纯函数
- `db_initializer.py`、`image_validate.py`、`mask.py`（脱敏）、`status.py`

### 3.3 `app/middleware/` —— 横切中间件（main.py 按序注册）
- `api_usage.py`、`monitoring.py`、`rate_limit.py`、`rbac.py`（`require_permission` / `PermissionChecker`）、`body_limit.py`
- 顺序（后 add 的在外层）：CORS → 异常处理 → 安全头 → 日志 → 指标 → 限流 → 认证限流

### 3.4 基类 / 基类型
- `models/types.py`：`JSONDict = JSON().with_variant(JSONB(), "postgresql")`（方言无关 JSON 列）
- `repositories/base.py`：`BaseRepository[ModelT]`（泛型 CRUD：`get_by_id` / `create` / `update`，**只 flush 不 commit**，事务由 Service 控制）+ `dml_rowcount` 工具
- `schemas/base.py`：`TZModel`（出参基类，datetime 统一本地化 + camelCase）+ `camel_config`
- `models/__init__.py`：ORM 模型注册中心（import + `__all__`，否则 alembic autogenerate 看不到）

## 四、两端公共能力的对应关系（值得注意的对齐）

| 能力 | 后端 | 前端 |
|------|------|------|
| 鉴权 / 权限 | `middleware/rbac.py`（`require_permission`、`PermissionChecker`） | `shared/security/permission-points`、`builtin-roles`、`hooks/useAuth` |
| 限流 | `core/rate_limit/` + `middleware/rate_limit.py` | `shared/security/rate-limiter`（按场景的 limiter 单例，用于 server action 端） |
| 错误码 / 错误响应 | `core/exceptions`（`ErrorCode` + `ErrorResponse`） | `shared/app-error.ts` + `shared/api/backend-client.ts` |
| 数据脱敏 | `utils/mask.py` | `shared/utils/mask.ts` |
| 时区 | `core/timezone.utc_to_local` + `schemas/base.TZModel` | `shared/utils`（日期格式化） |
| 事件总线 | `core/events.py` | `shared/events/event-bus.ts`（`appBus`） |
| 配置 / 常量 | `core/config` + `config_parts` | `shared/config` + `shared/constants` |

## 五、中心注册点（加公共件必须登记，否则不生效 / 散落）

- **后端**（详见 `AGENTS.md` 中心注册点表）：API 资源 → `api/v1/__init__.py`；ORM 模型 → `models/__init__.py`；业务异常 → `core/exceptions` 并继承 `BaseAppException`；错误码 → `core/exceptions/error_codes.py`；中间件 → `main.py`；配置项 → `core/config.py` + `.env.example`；启动/关闭任务 → `core/lifecycle/`；迁移 → Alembic。
- **前端**（详见 `components/README.md`）：通用 UI 件入 `src/components/<分层>/`，并从 `index.ts` 桶导出；复用阈值 GENERAL 2.4（重复 ≥2 次才抽，单文件 >500 行须拆）。组件化决策（如 `<DnaCard>` 提炼）以 `CS-Web-Frontend/tools/docs/FrontDoc-UID.md` §15 为唯一权威。
