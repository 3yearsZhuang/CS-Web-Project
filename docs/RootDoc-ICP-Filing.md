## 二、项目功能与技术架构

### 2.1 网站定位

计算机协会官网是面向在校学生的技术社团综合服务平台，以「项目优先、包容开放、成果驱动」为理念，涵盖 Web 开发、算法竞赛、人工智能、系统与安全、开源社区、创意编程六大技术方向。网站为非经营性、公益性的校园技术社区。

### 2.2 功能模块

网站采用前后端分离架构，共提供以下功能模块：

| 模块 | 服务功能 | 服务用途 |
|------|---------|---------|
| 认证与用户 | 邮箱注册登录、双因素认证（2FA）、GitHub 第三方登录、密码找回、个人资料管理、头像设置、设备会话管理、用户公开主页 | 用户身份注册与管理，保障账号安全 |
| 公告与通知 | 社团公告发布与展示、站内消息通知（点赞/回复/收藏/关注/@提及自动触发）、消息已读管理 | 社团信息传达与用户互动通知 |
| 入社申请 | 游客/登录用户提交入社申请（含兴趣方向、背景、自述），管理员审批后通知 | 社团招新与成员管理 |
| 活动管理 | 技术活动发布、活动筛选浏览、在线报名（限额/去重）、签到核销、活动自动归档、参与统计 | 线下/线上技术活动组织 |
| 技术社区 | 发帖（话题/文章）、评论与楼中楼回复、点赞与收藏、关注用户、内容 Feed 流、话题标签、社区系列、草稿保存、图片上传、内容搜索 | 校园技术知识分享与交流 |
| 工具集 | 在线考试（组卷/自动判分/排名）、资源库（提交/审核/下载）、任务发布板（认领/提交/审核）、积分体系（流水/排行榜/等级）、Auxilio 学习助手（薄弱点分析→资源推荐）、组件注册表 | 辅助学生学习与实践 |
| 管理后台 | 用户管理（启用/禁用/重置密码）、角色与权限管理、社区内容审核（隐藏/恢复/置顶/加精/删除）、举报处理、操作审计日志、密码重置审批 | 网站运营与内容管理 |
| 系统运维 | 健康检查、就绪探针、运行状态监控、异常日志记录 | 系统运维监控 |

### 2.3 技术架构

网站采用前后端分离架构：

```
浏览器 ──> Next.js 前端（BFF 薄转发） ──> FastAPI 后端 ──> PostgreSQL 数据库
            · 页面渲染与 UI              · 全部业务 API    · 数据持久化
            · API 代理（注入鉴权）       · 认证鉴权        · 异步驱动（asyncpg）
            · JWT 存 HttpOnly Cookie     · JWT 签发校验
```

**技术栈**：

| 层 | 技术 |
|----|------|
| 前端框架 | Next.js 16（App Router）· React 19 |
| 前端样式 | Tailwind CSS v4 · 双主题 |
| 后端框架 | FastAPI 0.139 · 全异步 |
| 数据库 | PostgreSQL（asyncpg 异步驱动） |
| ORM / 迁移 | SQLAlchemy 2.0 async + Alembic |
| 认证 | JWT 双令牌 · TOTP 2FA · GitHub OAuth |
| 缓存/限流 | Redis（可选，可降级为内存） |
| 部署 | Docker · 反向代理（Caddy/Nginx） |

**架构特点**：
- 前端为 BFF（Backend-for-Frontend）薄转发层，仅负责 UI 渲染与 API 代理，不承载业务逻辑
- 后端承载全部业务逻辑、数据存储、认证鉴权
- 分层架构：API 路由层 → 业务服务层 → 数据访问层 → 数据模型层，单向依赖
- 支持 HTTPS 加密传输（生产环境 `__Host-` 前缀 Cookie + Secure）

## 三、安全防护措施

### 3.1 身份认证安全

| 措施 | 说明 |
|------|------|
| JWT 双令牌 | access token（15 分钟短效）+ refresh token（7 天长效，轮换机制），登出/改密后令牌即时失效 |
| 令牌黑名单 | access token 通过 `jti` 黑名单撤销；refresh token 轮换锁定，重用检测自动吊销 |
| 双因素认证（2FA） | 基于 RFC 6238 的 TOTP，动态口令 30 秒有效；2FA 密钥使用 AES-256-GCM 加密存储；提供一次性备用码 |
| 第三方登录 | GitHub OAuth，state 一次性令牌 + 10 分钟过期，防 CSRF；邮箱已注册时不自动绑定，防账号接管 |
| 邮箱验证 | 注册需邮箱验证码，有效期 10 分钟；防枚举（不区分「用户不存在」与「密码错误」） |
| 密码安全 | bcrypt 哈希存储（输入限制 72 UTF-8 字节）；历史密码复用检测（默认 5 条）；改密同事务撤销全部会话 |
| 密钥轮换 | JWT 签名密钥支持零停机轮换（历史密钥兼容窗口）；定期轮换机制（建议每 6 个月） |

### 3.2 访问控制与权限

| 措施 | 说明 |
|------|------|
| RBAC 细粒度权限 | 基于角色-权限模型，`require_permission(resource, action)` 声明式鉴权，每个 API 端点独立校验 |
| 角色体系 | 预置 user / admin / root / content_moderator / exam_admin / task_publisher 六类角色 |
| 权限保护机制 | SELF_DEMOTE（禁自降）、SELF_DISABLE（禁自禁）、SELF_DELETE（禁自删）、SELF_APPROVE（禁自审）、LAST_ADMIN（保护最后管理员）、ADMIN_CROSS_PROTECT（管理员互保护） |
| 会话管理 | 用户可查看活跃设备会话（IP/User-Agent），支持远程登出 |

### 3.3 网络与请求安全

| 措施 | 说明 |
|------|------|
| HTTPS 加密传输 | 生产环境全站 HTTPS；Cookie 使用 `__Host-` 前缀（Secure + Path=/） |
| CORS 跨域控制 | 白名单制，仅允许配置的前端域名访问 |
| 安全响应头 | 安全头中间件统一注入 |
| 请求限流 | 全局限流 + 认证端点严格限流（登录/注册/刷新）；Redis 多实例共享计数，故障自动降级内存 |
| 请求体大小限制 | body_limit 中间件限制请求体大小，防大 payload 攻击 |
| Origin 校验 | POST 端点校验 Origin 白名单，防 Login CSRF |
| 反向代理头处理 | 可信代理 CIDR 配置，正确解析真实客户端 IP；不可信来源的转发头不参与限流 |

### 3.4 数据安全

| 措施 | 说明 |
|------|------|
| 密码加密存储 | bcrypt 哈希，不存储明文；旧 scrypt 哈希验证后自动升级 |
| 2FA 密钥加密 | TOTP secret 使用 AES-256-GCM 加密存储，主密钥独立配置 |
| 敏感信息脱敏 | 错误响应移除原始输入（防密码/令牌回显）；数据库异常不返回 SQL/约束原文；日志不记录带查询参数的完整 URL |
| 软删除机制 | 用户删除为软删除（`deleted_at`），释放唯一键但保留数据可追溯 |
| SQL 注入防护 | 全部数据库操作通过 SQLAlchemy ORM 参数化查询，无裸 SQL 拼接 |
| 路径遍历防护 | 头像/图片静态服务文件名严格校验，防目录穿越 |
| 头像上传校验 | 四重校验（大小 ≤2MB / MIME 白名单 / 扩展名白名单 / 文件头魔数），服务端生成文件名 |

### 3.5 日志与审计

| 措施 | 说明 |
|------|------|
| 操作审计日志 | 记录敏感管理操作（用户增删改、角色/权限变更、密码重置等），含操作人、时间、目标资源、操作类型 |
| 登录历史 | 记录登录成功/失败事件（best-effort），含 IP 与 User-Agent |
| 异常日志 | 运行时异常异步持久化，独立会话写入，不影响原始响应；异常日志仅超级用户可查 |
| 结构化日志 | loguru 结构化日志，生产环境 JSON 格式 + 文件轮转；禁止 `print` 输出敏感信息 |
| 可观测性 | 可选 OpenTelemetry（OTLP 导出 traces + metrics）；请求 ID 链路追踪 |

## 四、用户信息处理说明

### 4.1 收集的用户信息

| 信息类别 | 具体字段 | 收集方式 | 用途 |
|---------|---------|---------|------|
| 账号信息 | 用户名、邮箱、密码（bcrypt 哈希） | 用户注册时主动填写 | 身份认证与账号管理 |
| 个人资料 | 显示名、个人简介、头像、GitHub 主页链接、个人网站链接、技术方向标签 | 用户自行编辑（可选） | 个人主页展示与社区互动 |
| 第三方账号 | GitHub ID（OAuth 绑定） | 用户授权 GitHub 登录时获取 | 第三方登录与账号关联 |
| 设备信息 | 登录 IP 地址、User-Agent | 登录时自动采集 | 设备会话管理、安全审计、限流 |
| 行为数据 | 发帖/评论内容、点赞/收藏记录、关注关系、活动报名记录、考试记录、积分流水 | 用户使用功能时产生 | 业务功能实现与数据展示 |
| 安全数据 | 密码修改时间、密码历史（复用检测）、2FA 密钥（加密存储）、备用码（哈希） | 安全功能自动生成 | 账号安全保障 |

### 4.2 信息存储与保护

- **存储位置**：全部数据存储于服务器端 PostgreSQL 数据库，专属独立数据库，不与其他项目共用
- **传输加密**：生产环境全站 HTTPS 加密传输；JWT 存储于 HttpOnly Cookie，防 XSS 窃取
- **密码保护**：bcrypt 自适应哈希，不可逆；不存储、不记录明文密码
- **2FA 密钥保护**：AES-256-GCM 对称加密存储，主密钥独立配置于环境变量
- **IP 哈希**：社区浏览去重使用 IP 哈希（加盐），不存储明文 IP 用于浏览统计
- **访问控制**：仅授权管理员可访问用户管理功能；审计日志记录所有敏感操作
- **数据保留**：用户数据随账号存在；软删除后保留可追溯记录；异常日志支持按时间清理

### 4.3 信息使用范围

- 用户信息仅用于网站自身功能实现（认证、社区互动、活动管理、学习工具）
- 不向第三方出售、共享用户个人信息
- 不用于商业营销用途
- GitHub OAuth 仅获取用户 ID 与基础信息，不获取仓库等敏感权限

### 4.4 用户权利

| 权利 | 实现方式 |
|------|---------|
| 信息查阅 | 用户可在「个人资料」页查看自己的全部资料 |
| 信息更正 | 用户可自行编辑显示名、简介、头像、链接、技术标签 |
| 密码管理 | 用户可自助修改密码（需验证旧密码），改密后全端登出 |
| 账号注销 | 用户可删除账号（软删除），删除后不可登录、资料不再公开展示 |
| 会话管理 | 用户可查看活跃设备并远程登出 |
| 数据导出 | [规划中] 后续将提供个人数据导出功能 |

## 五、内容管理制度

### 5.1 内容类型与发布

网站包含以下用户生成内容（UGC）：

| 内容类型 | 发布权限 | 审核方式 |
|---------|---------|---------|
| 社区帖子（话题/文章） | 注册用户 | 先发布后审核 |
| 评论与回复（含楼中楼） | 注册用户 | 先发布后审核 |
| 入社申请 | 游客/登录用户 | 提交后管理员审批 |
| 活动报名 | 登录用户 | 自动确认（限额） |
| 资源提交 | 登录用户 | 管理员审核后公开 |
| 考试作答 | 登录用户 | 系统自动判分 |
| 用户头像上传 | 登录用户 | 系统自动校验（大小/类型/魔数） |

### 5.2 内容审核机制

| 机制 | 说明 |
|------|------|
| 角色分工 | `content_moderator`（内容审核员）专职社区审核；`admin`/`root` 兼具审核权限 |
| 审核操作 | 隐藏（违规内容下架）、恢复（解除隐藏）、置顶（重要内容置顶）、加精（优质内容标记）、硬删除（彻底删除） |
| 举报机制 | 用户可举报违规内容，管理员在后台集中处理举报 |
| 图片审核 | 上传图片经大小/类型/魔数四重校验；文件名服务端生成，防恶意文件 |
| 搜索过滤 | 社区内容支持搜索，管理员可控制内容可见性 |

### 5.3 违规内容处置流程

```
用户发布内容 → 系统自动校验（格式/大小）
                ↓
          内容公开可见（先发布后审核）
                ↓
    用户举报 / 审核员巡查发现违规
                ↓
    审核员处置：隐藏 / 加精 / 置顶 / 硬删除
                ↓
      处置记录写入审计日志（操作人/时间/对象）
```

### 5.4 管理员公告管理

- 公告由管理员统一发布与管理（增删改查）
- 公告在首页 Banner 展示，面向全体用户
- 公告操作记录审计日志

### 5.5 不良信息处置承诺

- 发现违法不良信息（涉政、涉黄、涉暴、涉赌等）将在 24 小时内处置下架
- 对发布不良信息的用户，管理员可执行禁用账号操作
- 配合公安机关依法调取相关日志与数据
- 建立内容巡查机制，审核员定期巡查社区内容
