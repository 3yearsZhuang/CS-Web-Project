列表 · 三组方案

设计语言边界：像素只注入元数据层与交互（标签/编号/角标/按钮/硬阴影），衬线标题与正文栈保持不变；盒装卡走 DNA 卡，列表行保持 border-b 分隔 + 紧凑密度（不套 DnaCard，避免撑大行高）。以下三档由「极简编辑」到「激进像素」。

A索引铁路 · Index Railway
纯编辑式索引：左侧像素编号 + 贯穿发丝铁路线 + 衬线标题 + 像素元数据行。无盒装、无浮起，hover 仅标题/编号转主色、箭头右移。最克制，与既有章节/时间轴语言同源。

标题底部虚影 · 评估

结论：可行，且贴合像素语言。 标题背后叠一份「虚影副本」是成熟的编辑式排印手法；在我们的设计体系里它天然对应硬偏移复制（而非模糊投影），与 DNA 卡硬阴影同源，不触发 §0「不发光/不浮起」与 §11 禁止清单——因为虚影是排印层的文字副本，不是盒装 box-shadow。

  • 令牌化：虚影色只用 var(--muted-foreground) / var(--primary) 低透明度，双主题自适应；绝不写死灰阶。
  • 层级：虚影 z-index 低于真实标题、pointer-events:none、aria-hidden，纯装饰、不可选中、无障碍安全。
  • 「底部」语义：虚影统一向下（并轻微向右）硬偏移，落在标题下方，符合「底部虚影」诉求。
  • 风险与规避：大号虚影在移动端可能显脏 → 用 clamp() 控制字号、缩小偏移与透明度；折叠态 Hero 标题保持纯净，虚影仅用于展开态章节/页面主标题。
  • 落地建议：封装为 .ghost-title 工具类 + 可选 <GhostTitle> 组件，经 data-text 单源驱动（方案 A/B），多步进用子 span（方案 C）。
A像素错位虚影 · Pixel Offset Echo
真实标题用衬线，背后叠一份像素字体的相同文本，向右下硬偏移、低透明度。衬线 × 像素的错位 = 最贴切的「融合」表达。

B衬线叠影 · Serif Echo
背后叠一份同族衬线、略放大、向下微偏移、极低透明度（≈0.12），纯编辑式「景深回声」。最克制、最安全，可无缝套用到所有章节标题。

C硬边双影 · Hard Stepped Pixel
背后叠 3 份像素文本，按 2px 步进硬偏移、主色递减透明度，形成复古游戏标题式的「硬像素投影」。像素身份最强，建议仅用于 Hero / 着陆主标题，避免正文章节滥用。
